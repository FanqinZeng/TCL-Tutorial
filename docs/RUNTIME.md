# 运行原理与技术边界

课程源 JSON 经 `scripts/build.py` 生成网站 JSON、Markdown、Tcl 示例、起始代码、答案和输入数据。网站为原生 HTML/CSS/ES modules，无 npm 构建依赖，hash 路由适合 GitHub Pages 的项目子路径。

## 真实 Tcl

`site/engine.js` 每次创建一个 `worker.js`。Worker 加载本地 RequireJS 和 Wacl WebAssembly，直接调用 `Tcl_Eval` / `Tcl_GetStringResult`。实测解释器为 Tcl 8.6.6，支持课程所需 TclOO。引擎是固定旧发行版，不声称最新。

加载超时 25 秒，执行超时 5 秒；停止或超时会 terminate Worker。每次重新创建解释器和虚拟文件系统；预置文件只写到 `/work`。虚拟文件与作者电脑、本地磁盘、SSH 或私人服务无连接。网站无服务端，没有商业 EDA 调用，不要求作者电脑开机。

## 结果视图与执行记录

执行后真实 Tcl 枚举用户最终全局变量、列表/数组与虚拟文件；UI 展示结果表、列表元素和文件内容。无法稳定观察的局部状态不编造。EDA 柱形数据来自实际结果中可解析的数字，并明确标注教学模型。

可选执行记录用 Tcl execution trace 观察真正调用的命令和返回值，最多 120 条。注释和未执行分支不会产生调用记录。记录是程序完成后的观察数据，不是暂停解释器的逐行调试。检查阶段移除观察器，评分调用不进入用户执行记录。代码失败时 UI 清除成功结果视图，并显示真实错误。

SVG 是教材示意，始终与本次运行结果分开标注。动态反馈可以关闭，并尊重 prefers-reduced-motion；没有音效或角色动画。

## 检查与本地验证

输出比较只忽略末尾换行；练习还在同一解释器中执行语义检查，过程题调用不同参数和边界。`workshop_stdout` 仅在评分阶段由运行器填入真实输出，支持基础输出练习检查。综合项目还有多种独立用例。

本地优先使用 `tclsh` 8.6+；开发环境也可以 `python3 scripts/check.py --all --tk`，通过 Python tkinter 接口使用真正的 Tcl 原生库（此工作区实测 9.0.4），并在独立进程与临时目录内执行。`tests/runtime.mjs` 使用同一份浏览器 WASM/Worker 在 Node VM 中验证，不使用模拟解释器。

## 学习记录与安全边界

草稿、手动阅读标记、最近位置保存在 localStorage，可导出 JSON；导入校验版本、键、课程范围、字段类型和 1 MB 大小，确认后替换；清空前确认。没有账号、排行、遥测或考试防作弊功能。

Worker 用于隔离页面交互和终止长任务，不是对任意恶意脚本的完整安全证明。不要在实验室放入敏感数据。可查看虚拟文件最大 64 KiB；变量预览最多 4096 字符，列表最多 64 项，执行记录最多 120 条。Tcl 本身仍计算完整结果。

浏览器不提供桌面 Tk 窗口、交互式 stdin、系统进程或真实 EDA。文件和命令行参数在每次运行前明确显示。Tcl 语言命令与工具扩展在第 16 节单独说明。
